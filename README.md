# Умные указатели

Учебная работа по управлению памятью в C++. Здесь написаны `UnqPtr<T>` для единоличного владения и `ShrdPtr<T>` для совместного. `MemorySpan<T>` хранит элементы в самописном `DynamicArray<T>`, а `MsPtr<T>` позволяет обращаться к ним и проверяет границы.

Код указателей разложен по заголовкам в `include/`: `UnqPtr.hpp`, `ShrdPtr.hpp` и `MemorySpan.hpp`. Если нужны все классы сразу, достаточно подключить `smart_pointers.hpp`. За основу `DynamicArray` взят из прошлых лабораторных, но в этой работе его буфер управляется через `UnqPtr<T[]>` — так контейнер сам служит проверкой работы умного указателя. Меню, замеры и функциональные проверки находятся в отдельных файлах в `src/`.

## Запуск

Нужны C++-компилятор с поддержкой C++20 и `make`.

```bash
make           # собрать программу
make run       # открыть меню с демонстрациями
make test      # выполнить функциональные проверки
make sanitize  # прогнать проверки под AddressSanitizer и UBSan
make benchmark # сравнить время и оценку памяти
make graph     # построить график по benchmark.csv
make clean     # удалить сборочные файлы
```

Первый запуск `make` создаёт каталог `build/`. `make clean` удаляет его; Git игнорирует сборочные каталоги и файл `HW1_sources.txt`.

В тестах проверяются перемещение и освобождение владения, счётчик `ShrdPtr`, преобразование между базовым и производным типами, удаление объекта при множественном наследовании, а также граничные случаи `MemorySpan` и `MsPtr`.

На Linux `make sanitize` включает проверку утечек. В поставляемом AppleClang на macOS LeakSanitizer недоступен, поэтому там проверяются ошибки доступа к памяти и неопределённое поведение, но не утечки.

## Бенчмарк

Замеры сравнивают обычные указатели, `UnqPtr`, `ShrdPtr` и стандартные `std::unique_ptr`/`std::shared_ptr` (STL-указатели используются только для сравнения). Проверяются наборы от 10 до 10 000 000 объектов. Для каждого варианта отдельно измеряются создание, доступ и удаление, включая освобождение буфера контейнера. Порядок вариантов перемешивается в каждом раунде; небольшие наборы повторяются, чтобы замер не сводился к шуму таймера. Для времени берётся медиана трёх раундов. Результаты записываются в `benchmark.csv`, график строит `plot_benchmark.py`.

Память учитывается заменой глобальных `operator new`/`delete`. На macOS и Linux берётся полезный размер выделенного блока с учётом округления аллокатором; служебные метаданные самого аллокатора не включаются. В CSV также записывается число выделений. Время по трём раундам сводится медианой, а память — максимальным пиком.

Чтобы собрать тексты файлов проекта в один документ для просмотра, выполни `make sources-txt`. Результат появится в `HW1_sources.txt`.
